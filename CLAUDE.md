# AMOLIE

SaaS-платформа для мастеров индустрии красоты. Главная задача — современная платформа онлайн-записи (booking).

## Философия разработки

Разрабатывать исключительно как **Production Ready**. Всегда думать как CTO крупной компании, отвечающий за долгосрочную эксплуатацию продукта.

- Не использовать временные решения ("на потом", заглушки, TODO-хаки).
- Не использовать legacy-код и устаревшие подходы.
- Использовать современные best practices 2026 года.
- Если существует более современное/лучшее решение — сначала предложить его и обосновать, и только после подтверждения пользователя — внедрять.
- Если есть риск (для стабильности, данных, безопасности, производительности) — предупредить заранее, до внесения изменений.
- Не ломать существующий функционал.

## Архитектурные принципы

- SOLID
- DRY
- KISS
- Clean Architecture
- Feature-Based Architecture

Требования к структуре:

- Каждый модуль должен быть независимым (низкая связанность, чёткие границы).
- Код должен быть легко масштабируемым.
- Всегда использовать строгую типизацию (TypeScript strict mode / аналог для используемого стека).
- Максимально использовать переиспользуемые компоненты.
- Никогда не писать огромные файлы — разбивать на небольшие, логически самостоятельные модули.

## Active Development Mode

Проект работает в режиме Active Development. Изменения вносятся небольшими логическими частями (каждый модуль — независимый и полностью рабочий), а не одним большим патчем.

После каждого завершённого задания — автоматически, без отдельного запроса на подтверждение:

1. Проверить код.
2. Запустить линтер (`pnpm lint`).
3. Запустить Type Check (`pnpm typecheck`).
4. Запустить тесты (`pnpm test`).
5. Исправить найденные ошибки.
6. Собрать Production Build (`pnpm build`).
7. Если настроен Git — сделать commit с понятным сообщением.
8. Если настроен удалённый репозиторий — выполнить push.
9. Если подключён Vercel — убедиться, что деплой завершился успешно (проверка commit status/checks, напр. через `gh`).
10. Обновить документацию, если она устарела по смыслу изменения.
11. Сообщить: что сделано, что изменилось, что проверить, какие есть известные проблемы.

CHANGELOG.md ведётся автоматически при каждом изменении, без отдельного запроса.

## UI/UX и дизайн

- Проект **Mobile First** — вёрстка начинается с мобильных экранов.
- Все страницы должны иметь идеальную адаптивность на всех разрешениях.
- Интерфейс должен ощущаться как современное нативное мобильное приложение.
- Обязательна поддержка **PWA**.

Ориентиры дизайна: Apple, Linear, Stripe, Notion.

Характер дизайна:

- большие отступы (generous whitespace)
- минимализм
- дорогой, премиальный внешний вид
- красивая, выверенная типографика
- современные, ненавязчивые анимации и переходы
