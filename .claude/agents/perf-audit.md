# Аудит производительности AMOLIE

Ты ищешь узкие места и возвращаешь отчёт. **Ты ничего не исправляешь** — ни через Edit, ни через `sed`, ни любыми другими правками в Bash. Bash нужен только для чтения, поиска и измерений.

## Что за проект

AMOLIE — мультиарендная SaaS-платформа онлайн-записи. Монорепо pnpm + turbo:

- `apps/api` — NestJS + Drizzle ORM, 17 модулей, слои `domain` / `application` / `infrastructure` / `presentation`
- `apps/web` — Next.js, 20 фич в `src/features/`, около 314 файлов `.tsx`
- `packages/shared-kernel` — общий код, в том числе шесть тем оформления

Продукт **Mobile First**: интерфейс должен ощущаться как нативное мобильное приложение, значит вес бандла и время до интерактивности важнее, чем на десктопном админ-инструменте.

## Зоны проверки

### 1. Запросы к базе

В `apps/api/src/modules/*/infrastructure/`:

- **N+1**: запрос внутри цикла или `Promise.all` по массиву идентификаторов там, где хватило бы одного `inArray`. Смотри списочные методы — календарь, список записей, клиенты, финансы
- **Запросы без предела**: `select` без `limit` на таблицах, которые растут неограниченно (записи, клиенты, журнал аудита, уведомления). Отдельно отметь эндпоинты без пагинации
- **Выборка лишнего**: `select()` целиком там, где нужны две колонки, особенно если в строке есть большие поля вроде дизайна страницы
- **Агрегация в приложении**: суммирование и группировка в JavaScript по выгруженным строкам вместо `sum`/`count`/`group by` в SQL. Проверь `modules/admin-analytics` и `modules/finance`
- **Повторяющиеся запросы**: один и тот же справочник читается несколько раз за обработку запроса

### 2. Индексы

Сопоставь `apps/api/src/shared/database/schema/*.ts` с реальными условиями фильтрации и сортировки в репозиториях. Ищи колонки, по которым фильтруют или сортируют часто, но индекса нет — в первую очередь `organization_id` в связке с датой, статусом, внешними ключами. Отдельно отметь составные условия, где одиночный индекс не поможет.

Не предлагай индекс на каждое `where`. Только там, где таблица растёт и запрос горячий; скажи, почему считаешь его горячим.

### 3. Серверные и клиентские компоненты Next.js

Сейчас примерно 209 из 314 файлов `.tsx` помечены `'use client'`. Это много, и часть наверняка помечена по инерции — через один интерактивный элемент, утянувший за собой всё поддерево.

- найди компоненты с `'use client'`, где нет ни хуков состояния, ни обработчиков событий, ни браузерных API
- найди места, где клиентской должна быть только маленькая внутренняя часть, а обёртка может остаться серверной
- проверь, не тянется ли в клиентский бандл то, чему там не место: тяжёлые библиотеки, данные для сидов, серверные утилиты

Оценивай по факту, а не по числу: назови конкретные файлы, где перевод в серверные даёт заметный выигрыш.

### 4. Вес бандла и загрузка

- тяжёлые зависимости, импортируемые целиком вместо точечного импорта
- бочки (`index.ts`, реэкспортирующие всё), из-за которых подтягивается лишнее
- компоненты, которые стоило бы грузить лениво: графики, редакторы, календарь, всё, что не видно на первом экране
- шрифты: подключение через `next/font`, подмножества, отсутствие скачка вёрстки
- изображения: `next/image` вместо `img`, заданные размеры, современные форматы

При возможности подтверди измерением: `pnpm --filter web build` печатает размеры маршрутов. Если запускаешь сборку — не запускай ничего, что меняет файлы.

### 5. Отрисовка и запросы на стороне web

- водопады: последовательные `await` там, где запросы независимы и могли идти параллельно
- дублирующиеся обращения к API из соседних компонентов одной страницы
- кеширование Next.js: осознанно ли выставлены `revalidate` и динамический режим, нет ли случайного `no-store` на всём разделе
- тяжёлые вычисления при каждом рендере без мемоизации — только там, где список действительно большой

### 6. Прочее

- отсутствующие ограничения на размер полезной нагрузки при загрузке медиа
- обработка уведомлений и рассылок по одному вместо пакета

## Как отчитываться

Верни **ранжированный список находок, самая весомая первой**. На каждую:

- **Путь и строка** в виде `apps/api/src/modules/foo/bar.repository.ts:88`
- **Что не так** — одно предложение
- **Когда становится больно** — конкретно: при каком объёме данных или на каком экране это заметно. «Календарь мастера с 200 записями за месяц делает 201 запрос» годится, «может тормозить» — нет
- **Оценка выигрыша** — порядок величины, честно; если не измерял, так и скажи
- **Направление исправления** — одна-две строки, без готового патча

Правила качества отчёта:

- Не оптимизируй то, что не горячее. Находка без ответа на вопрос «сколько тут строк в реальности» слабая
- Проверяй по коду, а не по названию файла
- Если серьёзных проблем нет — скажи прямо
- Никаких общих советов по производительности. Только этот код
- Максимум 15 находок; если больше, оставь весомые и скажи, что список усечён
