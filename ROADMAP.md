## Phase 1 — MVP (Foundation)

**Цель:** мастер может опубликовать страницу записи, клиент может записаться, обе стороны получают уведомления.

Модули в разработке (см. [TASKS.md](TASKS.md) для детальной разбивки):

- Auth & Users (единый вход на `beauty.lv` с редиректом на `{username}.beauty.lv`; регистрация мастера — закрытая, по инвайт-коду от админ-команды; роли).
- Organizations & Profile (профиль мастера/салона, локации).
- Services Catalog (услуги, категории).
- Scheduling (рабочие часы, исключения, расчёт доступности).
- Booking Engine (создание/отмена/подтверждение записи, защита от гонок).
- Notifications (email + SMS: подтверждение, напоминание, отмена).
- Публичная страница бронирования (мультиязычная, мобильная, PWA-базис).
- Личный кабинет мастера (расписание, список записей).
- Личный кабинет клиента (история записей).

**Явно вне Phase 1:** онлайн-платежи, отзывы, аналитика, маркетплейс-каталог, открытая самостоятельная регистрация мастеров без кода.

**Критерий готовности фазы:** реальный мастер может полностью заменить ручной способ записи (мессенджер/блокнот) на Beauty.lv для базового сценария one-to-one бронирования.

## Phase 2 — Payments & Monetization

**Цель:** платформа зарабатывает; мастера снижают потери от no-show через предоплату.

- Интеграция платёжного провайдера (приём онлайн-оплаты/депозита).
- Обработка возвратов при отмене по правилам.
- Биллинг подписки платформы (тарифные планы для организаций).
- Выплаты мастерам (маркетплейс-модель payouts).
- Финансовая история/отчётность для организации (базовая).

**Критерий готовности фазы:** мастер может включить обязательную предоплату для услуги, клиент может оплатить онлайн при бронировании, платформа собирает комиссию/подписку.

## Phase 3 — Growth Features

**Цель:** удержание и повторные визиты клиентов, инструменты роста для мастеров.

- Отзывы и рейтинг (с модерацией).
- Ответы мастера на отзывы.
- Аналитический дашборд (загрузка, доход, no-show rate, повторные клиенты).
- Расширенные уведомления (Telegram/WhatsApp — по приоритету рынка).
- Синхронизация с внешними календарями (Google/Apple Calendar).
- Промокоды/базовая программа лояльности.

## Phase 4 — Marketplace & Discovery

**Цель:** Beauty.lv становится каналом привлечения новых клиентов, а не только инструментом для существующих.

> Каталог сознательно не размещается на корневом `beauty.lv` (сайт-визитка без каталога, см. [ARCHITECTURE.md](ARCHITECTURE.md) §3.1) — точное расположение (отдельный поддомен/раздел) уточняется к началу этой фазы.

- Публичный каталог мастеров/салонов (поиск, фильтры: город, категория, цена, рейтинг).
- SEO-оптимизированные публичные страницы мастеров/салонов.
- Платное продвижение в каталоге (монетизация).
- Расширенный клиентский аккаунт (избранные мастера, история по всей платформе).

## Phase 5 — Scale & Platform

**Цель:** поддержка крупных салонов и сетей, техническая готовность к масштабу.

- Расширенные роли и права доступа (гранулярные разрешения внутри салона).
- Мультилокационные сети (единый аккаунт, несколько филиалов, сводная отчётность).
- Складской учёт материалов/товаров (опционально, по спросу рынка).
- Технический скейлинг: read-replica БД, возможное выделение отдельных модулей в независимые сервисы (см. [ARCHITECTURE.md](ARCHITECTURE.md) §5).
- Оценка целесообразности нативных мобильных приложений (iOS/Android) как альтернативы/дополнения к PWA.

## Phase 6 — AI & Automation

**Цель:** снижение рутины и повышение эффективности через интеллектуальные функции.

- AI-ассистент для клиента (помощь в выборе услуги/времени в диалоговом формате).
- Предиктивная аналитика no-show (риск неявки на основе истории клиента).
- Умные рекомендации по расписанию (оптимальное распределение слотов для мастера).
- Автоматизированные маркетинговые кампании (напоминания "давно не были", персонализация).
