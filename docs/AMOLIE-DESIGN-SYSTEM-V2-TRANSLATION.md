# AMOLIE — Как V2 «Материал» становится одной продакшен-системой кабинета

Утверждённые макеты Flowstep — визуальная северная звезда. Работающий кабинет — источник правды о функциях. Этот документ отвечает на один вопрос: **как первое становится слоем токенов и примитивов внутри второго, не породив третью параллельную систему.** Ни один экран здесь не переверстывается; ни одна архитектурная или продуктовая заморозка не трогается.

- Ветка **dashboard-v2**
- Дата **12 сентября 2026**
- Статус **план перевода, для решения владельца по §7 и затем для внедрения по §8**
- Входы **`docs/PRODUCT-UX-DIRECTION.md` (архитектура, M1–M9), `docs/AMOLIE-VISUAL-DESIGN-BRIEF.md` (бриф), `docs/AMOLIE-DESIGN-SYSTEM-V2.md` (направление F2), design guidelines файла Flowstep «AMOLIE — Dashboard Visual Exploration 2026», восемь утверждённых экранов ★ F2**
- Код **`globals.css`, `features/dashboard-shell/styles/*.css` (11 файлов, 136 КБ), `components/ui/*`, `shared-kernel/theme.ts`, `layout.tsx`**

> **Об именах файлов.** Задание ссылается на `docs/AMOLIE-FINAL-VISUAL-DIRECTION.md`. Такого файла в репозитории нет и не было ни в одном коммите. Финальным направлением здесь считаются `docs/AMOLIE-DESIGN-SYSTEM-V2.md` (коммит `b9c8611`) и design guidelines, прикреплённые к файлу Flowstep, — они совпадают по содержанию. Если под «final visual direction» имелся в виду другой документ, его нужно положить в `docs/` до начала Фазы 1.

Три дефекта, которые перевод закрывает попутно и которые нельзя тащить в новую систему:

1. **Geist загружен без кириллицы.** `layout.tsx` объявляет Geist с `subsets: ['latin', 'latin-ext']` — у Geist в Google Fonts кириллицы нет. Русский кабинет сегодня набран не «Geist», а первым запасным (`Inter` / `SF Pro Text`), и на разных машинах выглядит по-разному. Правило DESIGN_SYSTEM.md §3.2 «гарнитура без `cyrillic` не попадает в набор» нарушено самим кабинетом.
2. **Селектор выравнивания весов бьёт по общим примитивам.** `globals.css` приводит `font-medium/semibold/bold` к 400 на всей поверхности кабинета, а `Button` и `TabsTrigger` из `components/ui` набраны `font-semibold`. В кабинете кнопка теряет вес, который автор ей дал; классы набора (`t-section` с `font-weight: 600`) при этом вес держат. Два веса у одного слова в зависимости от того, каким слоем оно набрано.
3. **«Выбрано» выражено тремя разными способами.** Активный пункт сайдбара — белая карточка с рамкой и тенью (`.nav.is-on`); активная вкладка нижней панели — залитая пилюля под значком (`.bnav__pill.is-on`); активный сегмент — белая пилюля с тенью (`.seg > div.is-on`, `TabsTrigger`). V2 сводит всё к одному правилу 02 «выбранное поднимается».

## 2 · Пять принципов перевода

1. **Словарь имён не меняется, меняются значения.** `--bg`, `--bg-raised`, `--bg-sunken`, `--ink`, `--ink-soft`, `--ink-faint`, `--accent`, `--accent-contrast`, `--success/--warning/--danger` и их `-soft`, `--panel-radius`, `--card-radius`, `--field-radius`, `--control-radius`, `--shadow-*` — имена, на которых стоят `components/ui` и которые читают шесть миров публичной страницы. V2 наполняет их своими значениями на поверхности кабинета и добавляет имена только там, где у направления есть роль без имени (§3.9). Переименование ради красоты — запрещено: оно заставило бы трогать публичную страницу.
2. **Три слоя токенов.** Примитив (сырой цвет, число) → семантическая роль (что это на экране) → компонентный токен (что читает конкретный примитив). Тёмная тема — второй набор значений семантического слоя, примитивы у неё свои. Компонент никогда не читает примитив.
3. **Макеты — образец, а не пиксели.** Восемь экранов Flowstep не сведены между собой до пикселя: активный пункт «Today» на главной несёт полосу цвета глины (`#B5714B`), тогда как правило говорит «цвет — услуге, никогда навигации»; сайдбар на экране карточки визита нарисован плоской заливкой `#E8E1DA` вместо поднятой пилюли; контурные кнопки то на `#221C19/15`, то на `#D9D0CA`; кнопки панели инструментов — 40 px при законе 44. Там, где экран спорит с текстом `AMOLIE-DESIGN-SYSTEM-V2.md` или guidelines, **побеждает текст**; расхождения перечислены в §4 поимённо, чтобы их не перенесли как «так в макете».
4. **Чего нет в V2 — берётся из M1–M9.** V2 молчит о движении, иконках и о том, как выражать плотность в коде. Для этого действуют правила `PRODUCT-UX-DIRECTION.md` Часть 7: одна кривая, движение только на смену состояния 150–260 мс, без появления при загрузке (M5); один контурный набор иконок — набор кабинета, у Команды свой глиф (M8); две плотности по устройству (M6, уточнено V2 Частью 4).
5. **Пара цветов входит в токены только с замером.** Правило DESIGN_SYSTEM.md §4.4 и UI_GUIDELINES §2.1.1 остаётся законом. Замер сырой палитры F2 (§3.1) показал, что четыре её значения не проходят AA **текстом** на своих поверхностях; они остаются графикой (точки, полосы, контуры), а для текста выведены более тёмные ступени. Замер закрепляется тестом (§8, Фаза 1), а не таблицей в документе.

## 3 · Слой токенов

### 3.1 Цвет — светлая тема

Замер по WCAG 2.2: текст ≥ 4.5:1, графика и крупный текст ≥ 3:1, на той поверхности, где объект реально лежит. Значения из макетов, которые прошли, входят как есть; которые не прошли — сохранены для графики и получили текстовую ступень.

**Поверхности**

| Роль        | Токен                  | Значение  | Где работает                                                                           |
| ----------- | ---------------------- | --------- | -------------------------------------------------------------------------------------- |
| Основа      | `--bg`                 | `#F3EEE9` | Поле страницы, «стол»                                                                  |
| Поверхность | `--bg-raised`          | `#FFFFFF` | Любой объект: карточка, строка дня на телефоне, блок «выбрано», сайдбар-пилюля, панель |
| Ниша        | `--bg-inset` **новое** | `#F7F3EF` | Поле ввода, полоска клиента, заливка занятого блока, заметка в карточке                |
| Утопленное  | `--bg-sunken`          | `#EAE3DC` | Заблокированное время, недоступное окно, плоские пилюли, `disabled`                    |
| Розовый тон | `--bg-free` **новое**  | `#F9E8EE` | Свободное окно, дыра в дне, модуль «Время», подложка кнопки «Позвонить»                |

Сегодня `--bg-sunken` несёт две роли сразу — «ниша» и «выключено». V2 их разводит: ниша светлее белого на волосок, утопленное — заметно темнее. При переводе каждое использование `bg-bg-sunken` в `components/ui` (трек переключателя, hover строки, disabled-заливка, подложка сегмента) решается по смыслу: hover и трек → `--bg-inset`, disabled → `--bg-sunken`.

Приглушённым набраны подписи фактов, услуга в строке, «ended 10:00», «7 visits · last 12 Aug» — это данные, по которым мастер действует, а не декор. Что меняется в коде вокруг них:

- `services.color` и `service_categories.color` уже есть в базе (nullable, произвольный hex). Палитра свотчей `color-swatch-picker.tsx` сегодня — восемь цветов, среди них прежний акцент `#A63A5F`, леденцовый янтарь `#D9A441`, серый `#6B6B6B`. ### 3.2 Цвет — тёмная тема (кандидат)

V2 не даёт значений тёмной темы, только закон: «не инверсия, а тот же тёплый инструмент ночью: основа уходит в тёплый тёмно-коричневый, роза светлеет до читаемой». Набор макета имеет свою тёмную тему на холодном `#0E0E10` — она уходит вместе с набором. Ниже кандидат по тем же ролям, замеренный формулой; **утверждается только после замера на живом экране** (Фаза 1, тест на пары обязателен).

Правило 02 в темноте: тень на почти-чёрном не читается (вывод набора и `globals.css` совпадает), поэтому **«поднято» в тёмной теме — ступень тона на один шаг светлее плюс та же тень**: покоящаяся поверхность `--bg-raised`, поднятая — `--bg-lifted` (кандидат `#322A25`). В светлой теме `--bg-lifted` = `--bg-raised`, разницу несёт тень. Это единственное место, где тёмная тема получает имя, которого нет в светлой; компонент читает `--bg-lifted` в обеих и не знает разницы.

Радиус — свойство регистра плотности, а не элемента (DESIGN_SYSTEM.md §6 остаётся в силе). Все значения — из макетов.

| `--panel-radius` (поверхность, шторка)                 | 28 px               | 22 px               | 24 px   |
| `--card-radius` (блок, строка, ячейка дня, заметка)    | 16 px               | 16 px               | 10 px   |
| `--field-radius` (ниша поля)                           | 14 px               | 14 px               | 14 px   |
| `--control-radius` (кнопка, чип, пилюля, точка)        | 999 px              | 999 px              | 999 px  |

### 3.4 Тени

Глубина — смысл направления и то, что нельзя выпустить из-под контроля: **одна тень на объект**, четыре уровня на весь кабинет, ни одного литерала в компонентах. Значения из макетов, тон — чернила `rgba(34, 28, 25, α)`, не чёрный.

| Токен              | Десктоп                                                                     | Телефон                                                                    | Где                                                                                                  |
| ------------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `--shadow-control` | `0 6px 18px α.06`                                                           | `0 1px 3px α.10`                                                           | Пилюли панели инструментов, поиск, колокольчик, поднятый пункт сайдбара, выбранная ячейка ленты дней |
| `--shadow-rest`    | `0 14px 36px α.08`                                                          | `0 3px 14px α.05` (строка), `0 4px 18px α.07` (карточка ближайшего визита) | Поверхность в покое                                                                                  |
| `--shadow-raised`  | `0 14px 38px α.14`                                                          | `0 8px 22px α.12`                                                          | Выбранное: блок в календаре, строка под курсором, `aria-current`                                     |
| `--shadow-float`   | боковая панель `-18px 0 36px α.16`, поповер и тост `0 30px 80px -20px α.35` | нижняя шторка `0 -12px 40px -12px α.18`                                    | Всё, что действительно парит                                                                         |
| `--shadow-footer`  | `0 -10px 24px α.08`                                                         | то же                                                                      | Подвал панели вне прокрутки                                                                          |

Существующие имена `--shadow-soft / --shadow-lifted / --shadow-hero` (их читают `Tabs`, `Card` через `--surface-shadow`, публичные миры) получают алиасы: `--shadow-soft = --shadow-control`, `--shadow-lifted = --shadow-float`, `--surface-shadow = --shadow-rest`. В тёмной теме уровни те же, α выше, а `--shadow-rest` не `none`: без неё правило 02 в темноте держится одной ступенью тона, и это допустимо, но кандидат сначала смотрится на экране.

### 3.5 Два регистра плотности

Регистр — атрибут контейнера, а не набор классов на каждом экране: `data-density="spacious" | "compact"` на корне экрана (или на корне календаря в командном виде). Атрибут переключает **только** токены ниже; всё остальное — те же примитивы.

| Токен                                    | Просторный (десктоп / телефон) | Плотный                   |
| ---------------------------------------- | ------------------------------ | ------------------------- |
| `--row-h` (строка списка)                | 58 / 64 px                     | 44 px                     |
| `--slot-h` (30 минут в сетке)            | 28 / 30 px                     | 22 px                     |
| `--figure-size` (крупная цифра антиквой) | 44 / 38 px                     | не используется           |
| `--card-radius`, `--panel-radius`        | по §3.3                        | по §3.3                   |
| Содержимое блока                         | две строки, портрет            | одна строка, без портрета |

Сегодня высота часа живёт в двух местах: `calendar-model.ts` (`HOUR = 50`) и `app.css` (`repeating-linear-gradient … 50px`), и `grid-geometry.ts` считает по первому. В V2 у часа два значения (56 и 44), и разойтись им нельзя. Правило: **источник один — TypeScript** (`DENSITY.spacious.slotPx = 28`, `DENSITY.compact.slotPx = 22`), корень сетки пишет его инлайновым custom property (`style={{ '--slot-h': … }}`), CSS сетки читает только `var(--slot-h)`. Так геометрия перетаскивания и отрисовка считают одно число.

Что решает регистр (V2 Часть 4, без изменений): соло-мастер, телефон, панели — просторный; командный вид, двадцать визитов — плотный. Регистр выбирается по тому, сколько должно поместиться, а не по вкусу, и на телефоне плотного нет.

### 3.6 Типографика

**Гротеск — Onest, 400 / 500 / 600.** Тёплый гуманистический гротеск с полной кириллицей и латышскими диакритиками, уже загружен в `layout.tsx` с `cyrillic` и `latin-ext`, уже стоит на лендинге и публичной странице по умолчанию. Это закрывает дефект Geist-без-кириллицы (§1) и убирает из кабинета вторую гарнитуру интерфейса. Начертания 300 и 700 в кабинете не используются; селектор выравнивания весов из `globals.css` удаляется вместе с миром (M4).

**Антиква — открытое решение владельца № 1** (§7). Если оно утверждается, гарнитура выбирается из тех, что проходят жёсткий фильтр DESIGN_SYSTEM.md §3.2 (`cyrillic` + `latin-ext`) и уже загружены: **Playfair Display** (высокий контраст, ближе всего к «выразительной антикве» V2), **Cormorant Garamond**, **Spectral**. Instrument Serif, на который похож рендер Flowstep, кириллицы не имеет и в набор не попадает — приветствие «Доброе утро, Анна» обязано быть в той же гарнитуре, что «Good morning, Anna». Перед выбором проверяется одно: гарнитура обязана иметь **табличные цифры** (`font-variant-numeric: tabular-nums` реально применяется), иначе «10:30–12:00» в карточке ближайшего визита будет прыгать по ширине от визита к визиту. Слот — `--font-figure`; компоненты читают слот, не имя (тот же закон, что у `--font-page-display`).

**JetBrains Mono** перестаёт быть гарнитурой данных: V2 требует цифры табличными в основной гарнитуре, а не моноширинными. Остаётся только у инвайт-кодов и `kbd`.

## 4 · Три правила и остальное — как примитивы

Новый слой примитивов кабинета живёт в `apps/web/src/components/cabinet/` — отдельно от мир-независимых `components/ui` (которые читают только семантические токены и служат и публичной странице). Всё ниже — спецификация, не код.

### 4.1 `ServiceBar` — правило 01

Полоса 6 px во всю высоту объекта, `--control-radius`, цвет `var(--tone)` из услуги (`services.color` → категория → `serviceTone(id)` по четырём тонам). У выбранного блока в макете 8 px — оставляем 6, полоса не участвует в «поднято». Стоит слева вплотную: строка дня (оба регистра), блок календаря, крупная цифра времени в панели визита, строка «в кресле / дальше» в командном режиме. Никогда — у навигации, у человека, у окна, у блока «меня нет».

### 4.2 `lifted` — правило 02

Не компонент, а состояние любой поверхности: `data-lifted` / `aria-current="page"` / `aria-selected="true"` → `background: var(--bg-lifted); box-shadow: var(--shadow-raised)`. Никогда рамкой, обводкой, заливкой акцентом. Кольцо `focus-visible` остаётся (это доступность, а не выделение) — 2 px `--accent` с отступом 2 px. Носители: активный пункт сайдбара (белая пилюля + розовая точка справа; полоса цвета глины из макета главной — не переносится), выбранная ячейка ленты дней, выбранный блок календаря, активный сегмент вида, строка под курсором на десктопе, выбранное окно в форме записи.

### 4.3 `FreeTime` — правило 03

Розовый объект `--bg-free` с текстом `--accent-ink` и, где есть место, пилюлей `--accent` «Открыть». Три размера одного примитива: окно в сетке (высота `--slot-h`, `--slot-radius`), дыра в дне (42 px десктоп / 64 px телефон, `--card-radius`), модуль «Время» на главной (поверхность `--panel-radius`, тень `--shadow-rest`). Сегодняшнее свободное окно — пунктир чернилами по прозрачному (`.cal-free`) — уходит; UI_GUIDELINES «свободное время не красится ничем» отменено V2.

### 4.4 `Surface` — поверхность-объект

`background: var(--bg-raised); border-radius: var(--panel-radius); box-shadow: var(--shadow-rest)`, без рамки. Заменяет `Card` набора (`.card` с рамкой и `--shadow-1`) и `Card` из `components/ui` внутри кабинета (последняя остаётся публичной странице; `fill="rose|lilac"` и лиловый бенто уходят). Раздел внутри поверхности — воздух и одна волосяная линия во всю ширину, не своя коробка; `Surface` внутри `Surface` — ошибка, которую примитив ловит в dev-режиме предупреждением. Объекты стоят в 16–20 px друг от друга.

### 4.5 `Recess` — поле-ниша

`Input`, `Textarea`, `Select` из `components/ui` перестраиваются на токены: `background: var(--bg-inset); border: 0; border-radius: var(--field-radius)`; подпись `.type-meta` над полем; вспомогательная строка всегда в вёрстке; ошибка заменяет её текстом `--danger` с иконкой; фокус — кольцо `--accent` 2 px с отступом (бриф §15). `.input` набора с рамкой `--hair-strong` и `.field` уходят. Публичные миры это не трогает: они пишут свои `--field-radius` и `--border-strong`, а `border: 0` ставится компонентным токеном `--field-border-width` (кабинет 0, умолчание 1 px).

### 4.6 `VisitRow` — строка визита в двух регистрах

Один компонент, регистр из контейнера. Всегда: полоса услуги, время табличными, клиент, услуга, длительность, статус точкой и словом, маркер первого визита. Просторный: две строки, 58/64 px, кружок клиента (портрет — решение № 2, иначе инициалы); плотный: одна строка, 44 px, без кружка, имя мастера впереди клиента в командном режиме. Прошедшая — `opacity: .5`. Заменяет `day-row`, `today-attention-row`, строки ресепшена и списка записей.

### 4.11 Статус, люди, мелочи

- **Статус** — `Badge` (точка + слово) остаётся везде в строках; слово в цвете смысла читает `--*-ink`. Для шапки панели визита добавляется `Badge variant="pill"` (подложка `--*-soft`, точка, слово). Плашки `.badge.b-*` набора (100 мест) переводятся на эти два.
- **Люди.** `MemberAvatar` уже несёт портрет с точкой кадра; инициалы без фото — **один нейтральный тон** (`--bg-sunken` + `--ink-soft`), а не шесть цветов `avatarTint` («цвет — услуге, никогда человеку»). Клиенты — инициалы в том же нейтральном кружке; поле фото у клиента в базе отсутствует (решение № 2).
- **Полоска клиента** в панели визита — `Recess` с портретом/инициалами, счётом визитов, датой, заметкой, ссылкой «Открыть карточку».
- **Лента дней** — семь ячеек, точки услуг под числом, выбранная — `lifted`.
- **Пилюля счётчика** у заголовка «Нужен ответ» — единственный акцентный счётчик (в макете); у Календаря в сайдбаре — янтарный текст. Одно правило: счётчик того, что ждёт мастера, — `--warning-ink`; в заголовке модуля очереди — `--accent` пилюля. Это осознанное расхождение с M3 (акцент только в трёх ролях): V2 Часть 2 отменила «ровно три роли».

## 8 · Порядок внедрения

Каждая фаза — самостоятельный, полностью рабочий шаг с зелёными `lint / typecheck / test / build`, записью в `CHANGELOG.md` и своим коммитом; ни один экран не переверстывается, пока не стоят Фазы 1–2 (V2 Часть 12: «иначе система разойдётся на втором же экране»).

**Фаза 1 · Токены.** `tokens.css` (три блока), `legacy-aliases.css`, порядок импортов в `index.css`; удаление блока кабинета из `globals.css` (вместе с `.rise`, выравниванием весов, лиловым и бенто); расширение `@theme inline`; умолчания `:root` для новых имён; Onest как `--font-ui` в кабинете; `tokens.test.ts` на все пары §3.1–§3.2 через `contrastRatio` из shared-kernel; ESLint-предупреждение на инлайновые размеры. **Готово, когда:** кабинет открывается на новых цветах и радиусах без единой правки разметки экранов, тест пар зелёный, `visual:check` показывает ожидаемый разностный список (базлайны заведомо устарели — сравнивать списки, не ноль).

**Фаза 2 · Примитивы.** `components/cabinet/`: `Surface`, `ServiceBar`, `FreeTime`, состояние `lifted`, `VisitRow`; перестройка `Input/Textarea/Select` на нишу; варианты `Button`; `Badge pill`; одна `Sheet`; `data-density` и `DENSITY` в `calendar-model.ts`; `serviceTone` на четырёх тонах и палитра свотчей; `avatarTint` в один тон; нейтральный кружок клиента. Каждый примитив — со всеми шестью состояниями и тестом. **Готово, когда:** примитивы существуют и покрыты тестами, но ни один экран ещё не переведён (кроме тех, что примитивы задели через `components/ui`).

**Фаза 3 · Экраны, в порядке утверждённых макетов.** Главная (соло и командный режим) → Календарь (день, неделя, команда, список, лента дней, пять состояний, метка «сейчас») → Карточка визита → Форма записи → Телефон (шапка, панель вкладок, FAB, шторки). Каждый экран — отдельный коммит; классы набора в этом экране заменяются примитивами; правила `app.css`, оставшиеся без потребителя, удаляются в том же коммите. Здесь же — визуальная сторона R-1…R-11 из `PRODUCT-UX-DIRECTION.md`, поскольку макеты уже нарисованы с очередью, полоской клиента и «Write», а верстать главную дважды нельзя.

**Фаза 4 · Остальные разделы и снос.** Клиенты, Услуги, Страница, Команда, Финансы, Настройки, админка — только токены и примитивы, без переделки структуры; шесть шторок админки на `Sheet`; удаление `kit.css`, `legacy-aliases.css`, Geist из `layout.tsx`; ESLint-правило в ошибку; новые базлайны `visual:baseline`; `UI_GUIDELINES.md` §2.0–§2.7, §3, §4, §6, §8 переписываются, `DESIGN_SYSTEM.md` §4.3, §6, §7.2, §8, §9.1–9.4, §13.6 правятся, `Дизайн система AMOLIE/readme.md` получает пометку «лендинг и публичная страница; кабинет — по `docs/AMOLIE-DESIGN-SYSTEM-V2.md`», `.impeccable/design.json` — актуальную заметку о продуктовом мире. **Готово, когда:** `grep -r "amolie-app .btn\|t-meta\|b-green"` пуст, `pnpm lint` не находит инлайновых размеров, обе темы и три языка проверены на восьми экранах.

Проверка на каждой фазе: `pnpm lint`, `pnpm typecheck`, `pnpm test` (спорные файлы — через `npx vitest run`, turbo кэширует), `pnpm build`, `visual:check` разностью списков, ручной проход RU/LV/EN в обеих темах и с `prefers-reduced-motion`.
