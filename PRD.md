# PRD — Beauty.lv

Product Requirements Document. Версия 0.3 (черновик для утверждения). Дата: 2026-07-30.

## 1. Видение продукта

Beauty.lv — SaaS-платформа для мастеров и салонов индустрии красоты, объединяющая:

- **Инструмент онлайн-записи** для мастера/салона (календарь, услуги, клиенты, оплата).
- **Публичную страницу бронирования**, через которую клиент может записаться самостоятельно, 24/7, без звонков и переписки.
- (Фаза 4+) **Маркетплейс/каталог** мастеров и салонов для привлечения новых клиентов.

Аналоги на рынке: Fresha, Booksy, Treatwell, GlossGenius, Vagaro. Beauty.lv ориентируется на этот класс продуктов, но с фокусом на премиальный UX (Apple/Linear/Stripe/Notion-уровень) и рынок Латвии/Балтии (мультиязычность LV/RU/EN, GDPR по умолчанию).

## 2. Проблема

Независимые мастера и небольшие салоны сегодня чаще всего:

- ведут запись в мессенджерах, блокнотах или Google Calendar вручную;
- теряют клиентов из-за недоступности в момент, когда клиент готов записаться;
- не имеют системы напоминаний → высокий процент неявок (no-show);
- не собирают данные о клиентах и истории посещений;
- не имеют предоплат/депозитов → финансовые потери от отмен в последний момент;
- тратят время на рутинную коммуникацию вместо работы с клиентами.

## 3. Целевая аудитория и персоны

### 3.1. Мастер-фрилансер (Solo Master)

Индивидуальный специалist (мастер маникюра, барбер, косметолог, бровист и т.д.), работающий один, часто арендующий место в шеринг-салоне. Малый бюджет, ценит простоту и скорость настройки. Основная боль — самостоятельная запись клиентов без администратора.

### 3.2. Владелец салона (Salon Owner / Admin)

Управляет 2+ мастерами, одной или несколькими локациями. Нужны: управление расписаниями сотрудников, права доступа, сводная аналитика, финансовая отчётность, контроль загрузки персонала.

### 3.3. Клиент (Client)

Конечный потребитель услуг. Хочет быстро найти удобное время, записаться в 2–3 тапа с телефона, получить напоминание, иметь возможность отменить/перенести запись.

### 3.4. Администратор платформы (Platform Admin)

Внутренняя команда Beauty.lv. Управляет тарифами, модерацией, поддержкой, биллингом платформы, мониторингом.

## 4. Ценностное предложение

| Для кого     | Ценность                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| Мастер/салон | Меньше no-show, автоматизация записи, профессиональный вид перед клиентами, экономия времени администратора |
| Клиент       | Запись в любое время без звонков, напоминания, история посещений, оплата в приложении                       |
| Платформа    | Recurring revenue через подписку + комиссию с онлайн-оплат                                                  |

## 5. Бизнес-модель

Гибридная модель (подлежит финансовому подтверждению перед реализацией биллинга):

1. **SaaS-подписка** для мастеров/салонов — тарифные планы (Free/Starter/Pro/Business), различающиеся числом сотрудников, локаций, SMS-лимитом, аналитикой.
2. **Комиссия с онлайн-платежей** (предоплаты/депозиты), обрабатываемых через платформу (аналог Stripe fee + platform fee).
3. (Фаза 4+) **Продвижение в каталоге** — платное размещение/приоритет в маркетплейсе для новых клиентов.

Детали тарифов — предмет отдельного согласования, не фиксируются в этой версии PRD.

## 6. Объём MVP (Phase 1)

Функциональность, необходимая для первого релиза:

1. Вход/регистрация на `beauty.lv` (единая точка входа для всей платформы, с редиректом на `{username}.beauty.lv` после успешного входа мастера). Регистрация мастера в MVP — по инвайт-коду (закрытый запуск, см. §7.1 и [ARCHITECTURE.md](ARCHITECTURE.md) §10.1); вход клиента — email/телефон, OTP.
2. Профиль мастера/салона: название, описание, фото, адрес, контакты, часовой пояс.
3. Каталог услуг: название, длительность, цена, категория.
4. Управление расписанием: рабочие часы, перерывы, исключения (отпуск/выходной).
5. Публичная страница бронирования (уникальный URL) с выбором услуги → мастера (если салон) → времени.
6. Создание записи клиентом без регистрации (по номеру телефона) либо с аккаунтом.
7. Личный кабинет мастера: список записей (день/неделя/месяц), статусы (ожидает/подтверждена/завершена/отменена/неявка).
8. Уведомления: подтверждение записи, напоминание за N часов, уведомление об отмене (email + SMS).
9. Базовый профиль клиента: история записей.
10. Мультиязычность интерфейса: LV, RU, EN.
11. PWA: установка на домашний экран, офлайн-заглушка, адаптивность под мобильные устройства.

## 7. Функциональные требования по модулям (детально)

### 7.1. Auth & Users

- Единая точка входа/регистрации — `beauty.lv`. После входа мастер автоматически попадает на `{username}.beauty.lv/dashboard` (см. [ARCHITECTURE.md](ARCHITECTURE.md) §3.6).
- **Регистрация мастера в MVP — только по инвайт-коду**, выданному платформенной командой конкретному человеку (закрытый запуск, контроль качества онбординга вместо открытого самостоятельного набора). Открытая регистрация — возможное продуктовое решение будущей фазы, не MVP (см. [ROADMAP.md](ROADMAP.md)).
- Вход клиента (конечного посетителя записи) — email/телефон, OTP; для клиента регистрация без кода, как и раньше.
- Роли: `client`, `master`, `salon_admin`, `platform_admin`.
- Восстановление пароля, верификация email/телефона.
- Согласие на обработку персональных данных (GDPR consent) при регистрации.

### 7.2. Профиль мастера/салона

- Организация (салон) может иметь несколько мастеров и несколько локаций.
- Соло-мастер — организация с одним участником.
- Настройки: название, слоган, описание, логотип/обложка, адрес(а), соцсети, часовой пояс, язык по умолчанию.

### 7.3. Каталог услуг

- CRUD услуг, категории услуг, длительность (с учётом времени на подготовку/уборку), цена (фиксированная или "от"), привязка услуги к конкретным мастерам в салоне.
- Возможность назначить разную длительность/цену услуги для разных мастеров.

### 7.4. Доступность: мастер публикует окна вручную

**Продуктовое решение MVP:** без рабочих часов, без расписания, без алгоритма расчёта слотов. Мастер сам публикует конкретные окна времени, когда готов принять клиента — по одному, вручную. Это осознанное упрощение под основную аудиторию MVP (мастера маникюра): не нужно настраивать шаблон недели и исключения, достаточно открыть конкретные "свободна во вторник в 14:00".

- Мастер создаёт запись-окно: дата + время (без отдельного шага настройки длительности/буфера — окно и есть слот).
- Клиент видит **только** те даты и время, которые мастер явно опубликовал — ничего не вычисляется и не подставляется по умолчанию.
- Запись клиента переводит окно в статус "занято" — оно остаётся видимым (перечёркнутым), но недоступным для повторной записи.
- Отмена записи (клиентом или мастером) возвращает окно в статус "доступно".
- Идея регулярного расписания и алгоритмического расчёта доступности (буферы, рабочие часы, исключения) — сознательно исключена из MVP; при необходимости может быть добавлена отдельной опциональной фазой поверх этой же модели окон, не вместо неё.

### 7.5. Booking Engine (ядро продукта)

- Выбор даты → опубликованного окна → услуги (указывается в форме брони) → подтверждение (см. §7.4 — окно не вычисляется, а выбирается из явно опубликованных мастером).
- Защита от двойного бронирования (race condition при параллельных запросах).
- Статусы записи: `pending`, `confirmed`, `completed`, `cancelled_by_client`, `cancelled_by_master`, `no_show`.
- Правила отмены/переноса (например, не позднее чем за N часов).
- Групповые/повторяющиеся записи — вне MVP (Phase 3+).

### 7.6. Уведомления

- Каналы: Email, SMS, Web Push (PWA), (Фаза 2+) Telegram/WhatsApp.
- События: создание записи, подтверждение, напоминание (за 24ч и за 2ч — настраиваемо), отмена, перенос, запрос отзыва после визита.
- Шаблоны уведомлений на 3 языках.

### 7.7. Платежи (Phase 2)

- Онлайн-предоплата/депозит при бронировании (опционально включается мастером).
- Полная онлайн-оплата после услуги.
- Возвраты (refund) при отмене по правилам.
- Выплаты мастерам (payout) — маркетплейс-модель через провайдера (Stripe Connect или аналог).

### 7.8. Отзывы и рейтинг (Phase 3)

- Отзыв доступен клиенту только после завершённой записи.
- Рейтинг 1–5, комментарий, ответ мастера на отзыв.
- Модерация отзывов платформенным админом.

### 7.9. Аналитика и дашборд (Phase 3)

- Загрузка по дням/неделям, доход, no-show rate, повторные клиенты (retention), топ услуг.

### 7.10. Маркетплейс/поиск (Phase 4)

- Публичный каталог мастеров/салонов с фильтрами (город, категория услуг, рейтинг, цена). **Не размещается на корневом `beauty.lv`** — этот домен остаётся сайтом-визиткой о сервисе; точное расположение каталога — открытый вопрос (см. [ARCHITECTURE.md](ARCHITECTURE.md) §18).
- SEO-страницы мастеров/салонов.

## 8. Нефункциональные требования

- **Производительность:** первая отрисовка публичной страницы записи < 2с на 4G; доступные слоты рассчитываются < 300мс.
- **Доступность (Availability):** целевой SLA 99.9% для production.
- **Безопасность:** шифрование данных в транзите (TLS) и в покое, хэширование паролей (Argon2/bcrypt), защита от брутфорса, rate limiting на публичных эндпоинтах.
- **Соответствие GDPR:** платформа работает с персональными данными клиентов ЕС — обязательны: согласие на обработку, право на удаление и экспорт данных, минимизация данных, hosting данных в регионе ЕС.
- **Мультиязычность:** LV/RU/EN как базовые языки интерфейса и уведомлений с возможностью расширения.
- **Адаптивность:** Mobile First, идеальная адаптивность на всех разрешениях (см. [UI_GUIDELINES.md](UI_GUIDELINES.md)).
- **PWA:** установка на домашний экран, push-уведомления, работоспособность при нестабильном сетевом соединении.
- **Масштабируемость:** архитектура должна выдерживать рост от единиц до десятков тысяч организаций без переписывания ядра (см. [ARCHITECTURE.md](ARCHITECTURE.md)).
- **Наблюдаемость:** структурированные логи, трассировка ошибок, метрики бизнес-показателей (число записей, конверсия в бронирование).

## 9. Ключевые пользовательские сценарии (User Stories)

1. _Как клиент_, я хочу открыть ссылку мастера и записаться на услугу за 3 шага без регистрации, чтобы не тратить время.
2. _Как мастер_, я хочу видеть свой день в календаре и получать уведомление о новой записи, чтобы не пропустить клиента.
3. _Как мастер_, я хочу настроить рабочие часы один раз и не думать о пересечении записей.
4. _Как клиент_, я хочу получить напоминание за день до визита, чтобы не забыть.
5. _Как владелец салона_, я хочу видеть загрузку всех сотрудников на неделю, чтобы планировать смены.
6. _Как мастер_, я хочу включить предоплату для дорогих услуг, чтобы снизить неявки.
7. _Как платформенный админ_, я хочу видеть метрики использования по организациям, чтобы понимать здоровье продукта.

## 10. Метрики успеха (KPI)

- **Activation rate:** % зарегистрированных мастеров, опубликовавших рабочую страницу записи в течение 48 часов.
- **Booking conversion:** % посетителей публичной страницы, завершивших запись.
- **No-show rate:** снижение относительно исходного (целевое отраслевое значение — ориентир для сравнения "до/после").
- **Retention (мастера):** % активных организаций через 30/90 дней.
- **GMV (Gross Merchandise Value):** суммарный оборот записей, проведённых через платформу.
- **NPS клиентов и мастеров.**

## 11. Вне рамок MVP

- Открытая самостоятельная регистрация мастеров без инвайт-кода — MVP запускается закрыто (см. §7.1).
- Публичный каталог/маркетплейс мастеров на `beauty.lv` — см. §7.10 (Phase 4, и не на корневом домене).
- Мобильные нативные приложения (iOS/Android) — оценивается после валидации PWA.
- Программы лояльности, промокоды — Phase 3+.
- Интеграции с внешними календарями (Google/Apple Calendar sync) — Phase 3+.
- Складской учёт материалов/товаров — Phase 5+.
- AI-ассистент записи, предиктивная аналитика no-show — Phase 6+.
- Мультивалютность за пределами EUR — по мере экспансии за пределы Балтии.

## 12. Риски и допущения

| Риск                                                        | Влияние | Митигация                                                              |
| ----------------------------------------------------------- | ------- | ---------------------------------------------------------------------- |
| Двойное бронирование при высокой конкурентности запросов    | Высокое | Транзакционная блокировка слота на уровне БД, идемпотентность запросов |
| Низкая доставляемость SMS в LV/RU сегменте                  | Среднее | Резервный канал (email/push), выбор надёжного SMS-провайдера           |
| Отказ от использования мастерами из-за сложности онбординга | Высокое | Максимально простой onboarding-флоу, дефолтные шаблоны расписания      |
| Юридические требования GDPR/платёжного законодательства ЕС  | Высокое | Привлечение юридической экспертизы перед запуском платежей             |

## 13. Глоссарий

- **Организация (Organization)** — сущность верхнего уровня: соло-мастер или салон.
- **Мастер (Master/Staff)** — специалист, оказывающий услуги, член организации.
- **Слот (Slot)** — доступный интервал времени для записи.
- **No-show** — неявка клиента на подтверждённую запись.
- **GMV** — суммарный оборот, прошедший через платформу.
