# Скриншот-харнесс визуальных базлайнов (M0)

Реализация §16 [BRAND_STYLE_ARCHITECTURE.md](../../../../BRAND_STYLE_ARCHITECTURE.md).
Назначение — раннее обнаружение непреднамеренных визуальных регрессий живых
миров (Soft и Poster в первую очередь) на всём протяжении миграции M1–M8, а
также grayscale-кадры без изображений для монохром-теста §15.

## Что снимается

- **8 `designPresetKey`** (soft-studio, editorial, minimal, luxury, organic,
  neo-glass, poster, soft) — по одной фикстурной организации `demo-<key>`;
- **4 состояния**: `profile` (страница мастера), `prices`, `contacts`,
  `booking-sheet` (шторка записи, открытая на шаге услуг текущим поведением
  приложения: у Poster и Luxury — жестом «ближайшее окно», у остальных —
  «день → время → кнопка записи»);
- **2 вьюпорта**: `mobile` 390×844 (основной, проект Mobile First) и
  `desktop` 1440×900;
- **2 варианта**: цвет и `grayscale` (CSS-фильтр `grayscale(1)`, изображения
  скрыты — монохром-тест §15 «с чужим текстом»: данные всех восьми ключей
  одинаковы).

Итого 128 кадров: `baselines/<preset>/<state>.<viewport>[.grayscale].png`.
Базлайны коммитятся в git и переснимаются только вместе с намеренным
визуальным изменением в том же PR (процедура §16.4).

## Команды

```bash
pnpm --filter @amolie/web visual:baseline   # записать/обновить базлайны
pnpm --filter @amolie/web visual:check      # сверить текущий рендер с базлайнами
```

Фильтры прогона: `--preset=soft,poster`, `--viewport=mobile`,
`--state=profile,booking-sheet`, `--variant=color|grayscale`
(комбинируются; без фильтров — полный прогон).

## Как это работает

1. `fixtures.mjs` + `server.mjs` — фикстурный API-сервер (порт 4123) отдаёт
   публичные эндпоинты страницы мастера; Postgres и `apps/api` не нужны.
   Существующий сид БД не используется и не меняется.
2. `scripts/visual-baselines.mjs` поднимает `next start` (порт 4124) с
   `API_URL` на фикстурный сервер, `TZ=Europe/Riga` и замороженным временем
   (`scripts/freeze-time.cjs` через `NODE_OPTIONS`; в браузере — `page.clock`,
   обе стороны согласованы, поэтому SSR и гидратация видят одно «сегодня»).
3. Playwright (chromium) снимает каждое состояние после `networkidle` и
   `document.fonts.ready`, с `prefers-reduced-motion: reduce` (закон А5
   схлопывает анимации — кадры стабильны по построению).
4. `visual:check` сравнивает свежие кадры с базлайнами через `pixelmatch`:
   провал — доля diff-пикселей > 0.1% площади кадра или изменение размеров
   кадра. Актуальные кадры пишутся в `current/`, diff-кадры — в `diffs/`
   (оба каталога в .gitignore).

Харнесс работает с production-сборкой (`next start`), а не с dev-сервером —
кадры соответствуют тому, что видят клиенты. Если `.next` отсутствует,
сборка запускается автоматически; иначе используется существующая — после
правок кода пересоберите `pnpm --filter @amolie/web build` перед прогоном.

Первый запуск требует браузер: `pnpm --filter @amolie/web exec playwright
install chromium`.

## Границы

- Провал `visual:check` — сигнал, а не приговор: либо регрессия (чиним),
  либо намеренное изменение (переснимаем базлайн в том же PR, §16.4).
- Харнесс не заменяет unit-тесты (Vitest) и не является тест-раннером —
  один скрипт с двумя режимами, как записано в §16 и §13.3.
